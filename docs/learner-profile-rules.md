# Learner profile: update rules (W6, draft v0.1)

The profile remembers how well each learner masters each **SubSkill** of the Knowledge Graph (25 SubSkills, see `kg/data/nodes.csv`). It is the input of the personalised recommendation planned for W7.

## 1. State

One state per (learner, SubSkill):

| Field | Type | Meaning | Initial value |
|---|---|---|---|
| `mastery` | float in [0, 1] | estimated mastery (0 = weak, 1 = strong) | **0.5** |
| `evidence` | float >= 0 | sum of the weights of all events applied so far | 0 |
| `last_update` | timestamp | time of the last event (kept for the time decay of W7) | none |

Reading a mastery value: below 0.4 = weak, 0.4 to 0.65 = developing, 0.65 or more = strong. This is only used to display and to rank; it never changes the state.

## 2. Events

An event updates the state of **one** SubSkill. One attempt produces several events (one per SubSkill).

| `event_type` | When | `outcome` (y) | Weight (w) |
|---|---|---|---|
| `ERROR` | The AI reports an ErrorType that `AFFECTS` the SubSkill in a graded Writing or Speaking attempt | 0 | 1.0 |
| `CLEAN` | The SubSkill belongs to a Criterion of the graded skill, and the attempt has no error on it | 1 | 0.3 |
| `DRILL` | The learner finishes a practice drill that `PRACTICES` the SubSkill | score / total (0 to 1) | 1.0 |

Rules:
- One `ERROR` or `CLEAN` event per SubSkill per attempt, however many errors the AI found on it (a long essay is not punished more).
- `CLEAN` weighs less than `ERROR` because the AI does not find every error, so "no error found" is weaker evidence than "error found".
- Events are applied in time order. Events with the same time are applied in file order.

## 3. Update formula

For an event with outcome `y` and weight `w`, on a state with `mastery = m` and `evidence = e`:

```
eta       = max(ETA_MIN, 1 / (e + 3))      # learning rate, smaller when there is more evidence
m_new     = clamp(m + w * eta * (y - m), 0, 1)
e_new     = e + w
last_update = event time
```

Parameters (one config object in the code):

| Name | Value | Meaning |
|---|---|---|
| `INITIAL_MASTERY` | 0.5 | start value of a new learner |
| `ETA_MIN` | 0.10 | the profile never becomes frozen |
| `OFFSET` | 3 | the first event moves the mastery by at most 1/3 of the gap |
| `W_ERROR`, `W_CLEAN`, `W_DRILL` | 1.0, 0.3, 1.0 | event weights |

Example: a new learner has an `ERROR` on `SUB_ARTICLE`: eta = 1/3, mastery = 0.5 + 1/3 * (0 - 0.5) = 0.333. A second `ERROR`: eta = 1/4, mastery = 0.333 - 0.083 = 0.25.

## 4. Out of scope for W6

- **Time decay** (mastery drops when the learner does not practise): decided for W7. `last_update` is stored so that it can be added without a migration.
- **Prerequisites** (`PREREQUISITE_OF`) and **band level**: used by the recommendation in W7, not by the update.
- Pronunciation: no data yet (always `null`).

## 5. Code interface (shared by backend and evaluation)

```
SkillState { double mastery; double evidence; Instant lastUpdate }       // new learner: 0.5, 0, null
Event      { String userId; Instant time; String subskillId; EventType type; double outcome }
SkillState update(SkillState state, Event event)                         // pure, no database access
```

`outcome` is already in [0, 1]. The weight comes from `event_type` (table above), so the same code reads the real log and the synthetic log.

## 6. Event log format (`interaction_log` and the synthetic CSV)

Columns: `user_id, time, subskill_id, event_type, outcome, source_id`
- `time`: ISO-8601 UTC.
- `source_id`: id of the attempt or drill that produced the event (groups the events of one attempt).

## 7. Synthetic learners (how the test data is made)

Generated by `data/learner_sim/generate_logs.py` (details in `data/learner_sim/README.md`). The generator uses a **hidden true mastery** and does **not** use the formula above, so that evaluating the formula against it is meaningful.

- 60 learners, 8 weeks, fixed random seed.
- Each learner has a hidden true mastery per SubSkill (average 0.5, differs between learners). It grows a little after each drill of that SubSkill.
- Each week: 2 Writing or Speaking attempts and 3 drills, drills mostly on weaker SubSkills.
- In an attempt, a true error happens with probability `0.8 * (1 - true mastery)`. The AI finds a true error with probability 0.7 and reports a false error with probability 0.05 (the AI is not perfect).
- A drill score is `Binomial(6, 0.25 + 0.7 * true mastery) / 6`.

## 8. Success criterion (shared with the evaluation issue)

Compare the estimated mastery with the true mastery at the end of each week: report mean absolute error (MAE) and correlation, and how they change with the number of events.

- Baseline: a profile that always says 0.5 has MAE about 0.16 (the true mastery does not spread much), so MAE alone is a weak measure. The correlation is the main measure.
- Target after 8 weeks: MAE below 0.15 and correlation above 0.6. A first check with the default parameters gave MAE 0.128 and correlation 0.63 (week 1: 0.159 and 0.28; week 4: 0.142 and 0.50).
